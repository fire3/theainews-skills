# One-Pass Cover Prompt Template

完整提示词按以下结构组织，存为 `prompts/01-cover-<slug>.md` 后交给
chromebot。每张封面都必须自包含：风格、版式、逐字文本、约束全部写全，
不依赖任何外部文件。

> 头部必须注明 `风格 + 版式`（如 `scientific + left-text-right-visual`），
> 并在写提示词前对照 `style-system.md` 的「版式池/选择自查」确认：
> 版式不与最近 3 张封面重复，且没有回落到默认的底部三卡。

## 结构

1. **角色与用途**（1–2 句）：16:9 文章封面，所属站点/媒体气质。
2. **风格规范**：从 `style-system.md` 选中风格的整段规范复制进来
   （背景/排版/配色/视觉元素/Do/Don't），并注明所选强调色变体。
3. **版式**（先定构图，再填充内容）：从 `style-system.md`「版式池」选一套，
   在提示词中写清楚各文字区块与视觉主体的位置。对照版式池把选用理由列出，
   避免与最近 3 张封面重复。
   - L-hero-center：居中主视觉，数据融入标题/副标题，不排卡行。
   - L-left-text-right-visual：左文右图，右栏满幅视觉，要点竖排。
   - L-big-number：中央超大数字/关键词即核心，其余只留 1–2 行。
   - L-split-panel：硬切分栏/斜切叙事，事实用分栏或时间线组织。
   - L-bottom-cards：底部三卡（备选，严禁连用）。
4. **视觉主体**：与文章主题对应的抽象视觉（硬件/流程/图标/隐喻），并明确
   「所有图形与装饰上禁止出现任何文字、字母、数字、符号、logo」。
5. **图内文字**（逐字，全图唯一文本，组织方式随版式而定）：
   - 标题：<逐字中文标题>
   - 副标题：<一行关键事实>
   - 数据/要点（可选）：<2–3 个短句，按版式组织，不一定做成底部卡片>
   - 提示词中标注易错英文名逐字母拼写；要求「不得增删改译任何字符，每串
     只出现一次」。
6. **安全边距与约束**：左右 ≥6%、上下 ≥5%；无 logo、无水印、无页码、无引号
   装饰；除引用字符串外不允许任何其他字符出现。

## 生成与迭代

- API 失败重试一次。
- OCR 发现错字/乱码/多余文字 → 新建 `-v2` 提示词与输出路径重新生成；
  绝不叠字修补。
- 只有裁切、缩放、转格式允许在生成后执行（如 JPEG q90）。

> 提示词里不得出现十六进制色码或任何带编码的颜色（如 `#FFFFFF`、`rgb(...)`），
> 配色一律用「深海军蓝」「亮青」「珊瑚红」这类文字描述，避免编码被模型当作图内
> 文字渲染造成泄露/乱码。封面不强制携带品牌字标/logo，可省略。
